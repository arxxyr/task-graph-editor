# 日志选择与分析

顶栏的「日志分析」与「参数」「流程图」并列；切换视图保留当前任务图的未保存内容。

## 使用

页面按「选择日志」「分析设置」「分析结果」三张卡片组织：前两张收在默认展开的「选择与设置」
折叠区内，报告生成后自动收起，可随时再展开修改；「报告目录」「开始分析」「取消」固定在
滚动区外的页面头部，「选择与设置」下方的状态条以图标加文字显示当前进度和结果。

1. 在「选择日志」卡片的来源行导入日志：「导入本地」菜单选择日志文件（支持多选）或日志目录，
   本地分析无需 SSH 连接；远程日志使用左侧已建立的 SSH 连接，在远程目录输入框确认路径后
   点击「读取远程」。默认浏览 `~/.ros/log`，也可手工填写目录。
   只显示有效的 `YYYYMMDD` 日期目录及 `master_control.log` / `master_control_*.log` 主控日志，
   隐藏 ROS 启动目录和其他组件文件。日期目录按日期倒序，文件按名称末段创建时间倒序（不按 PID 或修改时间）。
2. 位置行的「上一级」返回上级目录，旁边的说明文字标明当前远程目录或本地文件来源。
   列表逐行展示：目录行是文件夹图标加名称，文件行是文件图标加名称和大小；点击日期目录进入。
3. 点击文件切换选择，选中行高亮；筛选行按文件名过滤，底部行显示
   「共 N 项 · 已选 M 份 · 第 x/y 页」，并提供全选、清空和翻页按钮。
   筛选不会取消已选中的其他文件，开始分析时处理全部已选文件；没有可显示条目时列表给出图标和操作引导。
4. 在「分析设置」卡片用分段控件选择模式（动作与轮次 / 工件节拍），模式说明随选择切换；
   复选框组确认暂停和错误轮次口径，工件选项子面板按模式显隐。默认收起的「口径说明与输出位置」
   可更改报告根目录。点击「开始分析」。远程文件先下载到本次报告目录，再本地分析。
5. 分析完成后自动收起设置，「分析结果」卡片展示当前日志：头部在多份输入之间切换，
   统计卡给出纳入数量、平均、最快、最慢，逐轮表列出北京时间、原始耗时、扣除量、统计耗时
   和纳入状态。表格带斑马纹，耗时条在整份日志中使用同一比例，纳入与排除以状态徽章区分。
   点击轮次展开结束时间、原因和本轮甘特图。排除轮次仍可查看，但不参与汇总；分页不改变统计口径。
   「原始报告与导出文件」折叠收纳摘要、CSV 和交互报告，头部固定的「报告目录」可访问全部产物，
   滚动内容时入口始终可见。

动作与轮次模式显示扣除暂停后的有效耗时，工件节拍模式显示按本次搬框等待设置计算的净周期；
二者保留各自既有口径。旧版报告没有逐轮概览，重新分析后生成。

内置分析器支持 master_control 新旧时间戳格式、轮次检测、暂停扣除、导航、预打舵、
机械臂、头部、腰部和夹爪统计。其他类型的普通日志可能无法识别，会逐文件提示失败。
选择目录不会递归扫描子目录；远程目录可逐级浏览，本地可以继续通过系统选择器选择子目录。

## 产物与保护

默认根目录是用户主目录下的 `task-graph-editor-reports`。
每次分析独占创建 `analysis-日期时间-进程号-序号` 子目录，不清理或覆盖旧报告。
同名日志也分别写入 `log-001`、`log-002` 等目录。

产物包括原分析器生成的分析 CSV、动作时间轴、轮次甘特图、轮次耗时统计 CSV/PNG/TXT，
以及标准时间线 `timeline.json`、逐轮概览 `round_overview.json`。多个成功结果按绝对时间合并成 `merged_gantt.png`；
不同日志的事件身份添加来源前缀，避免轮次编号碰撞。各文件独立检测轮次，不跨文件拼接未完成动作。

`report.json` 保存完整分析回执，`request.json` 记录本次输入，`diagnostics.txt` 保存分析进程诊断。
个别文件失败不会丢弃其他文件的结果。没有可绘制数据时可能没有对应图表，页面按实际产物列出。
中文报告使用应用内嵌的更纱黑体，不要求安装系统 CJK 字体。

分析在同一可执行文件启动的独立进程中执行，不初始化窗口或 GPU。
「取消」终止分析进程，已经生成的部分报告保留。远程下载按数据块检查取消，当前阻塞的 SFTP
调用仍受 SSH 会话超时约束；取消日志操作不会主动断开任务图的 SSH 连接。
下载中失败的本地半文件会删除，已下载的完整文件保留。

远程浏览记录实际目录和连接代次。换连接、断开后，旧回执不能替换列表或启动分析；
操作前重新校验来源，避免旧主机的选择被解释为新主机文件。
远程操作只列目录和读取文件，不修改远端日志。

## 开发验证

```bash
cargo fmt --all
cargo clippy --all --all-targets -- -D warnings
cargo test --all
cargo build --all-targets --timings
```

合成样例位于 `tests/fixtures/master_control.txt`，不包含真实机器人数据。
分析回归检查中文 PNG、CSV、两份同名输入、时间线身份及暂停检测；
界面回归检查跨帧创建、筛选选择、旧按钮与过期连接回执。

来源及本地适配见 `3rd-party/log-analyzer/UPSTREAM.md`。

仅检查日志页布局时，可使用：

```bash
TGE_SCREENSHOT=/tmp/task-graph-editor-logs.png TGE_SCREENSHOT_VIEW=logs cargo run
```

文件列表和每份日志的报告均分页显示，避免一次生成大量控件；报告区可切换查看每份输入的结果。

## 统计口径与筛选

日志页是应用内的独立标签。进入后隐藏任务图文件列表和编辑操作，SSH 连接继续共用；
返回参数或流程图时恢复原有实体、选择和未保存状态。

先选择日志，再确认口径。两种模式互不混用：

| 模式 | 周期定义 | 主要产物 |
|---|---|---|
| 动作与轮次 | 来源分析器的初始 / 常规 / 最终循环标记 | 动作 CSV、逐轮甘特图、常规轮次统计 |
| 工件节拍 | 同进程相邻 `normal_nav_pick` 创建记录之间的前闭后开区间 | 逐轮证据 JSON、统计 JSON、Markdown、自包含交互 HTML |

“纳入有暂停的轮次”和“纳入有错误的轮次”默认不勾选。动作与轮次模式仅筛选
常规轮次耗时图表及相应统计 CSV，完整甘特图和动作明细保留；
`statistics_selection.json` 记录每轮是否纳入及原因。无有效统计样本时不生成空的耗时图。
该模式沿用来源分析器的暂停扣除和浮点时间，不等同于下面的工件节拍口径。

工件节拍提供北京时间日期（留空为全部日期）、人工重试 / 跳过 / 取消轮次纳入开关，
以及“扣除明确的阻塞搬框等待”（默认开启）。配置不绑定设备名、机器路径或某一天。
当前工件节拍规则适用于项目已有的气密工件流转节点：

- 起点为 `ROS2ActionNode[normal_nav_pick] - 创建成功`，终点为同进程下一次创建。
- 区间内必须依次且各一次成功发布 `normal_arm_pick_merged`、
  `normal_arm_leak_grab_and_place_station_1_merged` 或 `station_2_merged`、`normal_arm_put_merged`。
- 未闭合、成功记录缺失 / 重复 / 乱序始终排除，不能通过勾选强行纳入。
- ERROR、FATAL、CRITICAL 级别、明确执行失败和非零执行结果码构成执行错误；
  不凭“检测失败”等产品检测文字判故障。错误日志行数不是独立故障次数。
- 暂停按进程配对并合并重复开始；恢复、重试、跳过、取消和重新启动关闭已观测状态。
  未闭合暂停只延续至本进程观测终点，不跨重启。取件导航重试向后关联紧随其后的取件锚点。
- 仅自动扣除 `wait_pending_box_before_pick_seq` 开始至同线程
  `wait_pending_box_before_pick_done action=box_done success` 的可靠阻塞区间。
  多区间先求并集，再与每轮和各阶段求交集。异步搬框提交、正常 Sleep 和调度开销不扣除。
  重复开始、线程不匹配、控制中断或未闭合时保留不确定性证据，不猜测扣除；其他带
  `wait` / `box` 的顺序节点记录为待核查候选，不擅自套用规则。

工件模式读取跨日文件全文；新格式无时区时间显式解释为北京时间，旧格式 epoch 按 UTC
转换，均用整数微秒计算。日期只筛选周期起点。以日志启动头分隔进程，文件之间不拼接。
同源身份的不同采集副本仅保留最长且前缀一致的一份；同源内容冲突明确报错。
末尾未换行的半行不参与解析。数据审计记录每份来源的实际起止时间、忽略行数和副本选择。
没有源身份头的文件只识别路径相同或内容相同的副本，不能推断任意裁剪片段的共同身份；
选择此类日志时应只保留一份可靠源文件。日志未提供的进程重启或其他自定义节点语义也不能猜测。

分析开始时冻结配置；忙碌期间禁止改动统计选项。修改配置在下一次分析生效，页面保留
上一次报告，不把旧结果解释为实时重算。工件报告的工位 / 起始小时筛选则即时更新统计、
散点和平均线，支持原始 / 净周期切换、极值和最长等待定位、点击周期查看源行证据及
已排除周期列表。报告显示四阶段分解，保留原始时间轴；流程图由 Archify 生成并内嵌。
所有统计数据可从 `workpiece/cycles.json` 和 `workpiece/statistics.json` 复核。

分析实现位于 `src/log_analysis/workpiece.rs` 及子模块；合成测试覆盖跨日、重启、半行、
副本冲突、暂停重叠、错误级别、恢复轮归属、等待不确定性、微秒加总和报告脚本转义。
该能力只读取日志，不修改机器人配置或运行状态，也不把工件流转轮数称为合格产量。

主控文件名只支持 `master_control` 前缀，标准格式为 `master_control_PID_HHMMSSffffff.log`；
小数秒最多支持 9 位。同一创建时刻按文件名稳定排序；无创建时间或时间无效的旧主控文件保留在列表末尾。
